Formule et conventions
----------------------
V = cash global fini + cash alloué + valeur de marché des positions + réserve
FIXED signée. La réserve n'est jamais remise à zéro ni rendue réinvestissable.

Au premier financement net positif du cycle : I = 100 et U = V / 100.
Sans apport : I = V / U.
Lors d'un apport externe A, après valorisation des positions au cours du jour :
  U_après = U_avant + A / I_avant
  V_après = V_avant + A
  I_après = V_après / U_après = I_avant.
En capital fini, allouer CT déplace du cash interne : aucun changement de U.
En capital illimité, chaque première allocation CT effective est un apport ;
les allocations du jour sont agrégées avant les achats, à valorisation identique.
Un financement sans quantité achetable reste du cash effectivement alloué.
Le premier apport constitue la valeur initiale, les suivants sont soustraits
pour déterminer le PnL du cycle.

H = maximum de I depuis le début du cycle ; DD = (H - I) / H.
Déclenchement strict : (H - I) * 100 > H * seuil_pct.
Les parts, l'indice et le sommet sont calculés en fractions rationnelles exactes
à partir des montants Decimal. Les valeurs JSON sont converties en Decimal
pour affichage uniquement. Aucune tolérance numérique ne modifie le seuil.
Cela évite un faux dépassement lié à une division décimale périodique après
un apport. Ce n'est ni un pourcentage du PnL maximal ni du capital investi.

PnL_cycle = V_fin - V_début - apports ultérieurs du cycle.
Après liquidation complète, ce montant est réalisé. Pour un cycle ouvert ou
encore en liquidation, il inclut la valorisation des positions restantes.
Les PnL réalisés, gains/pertes, compteurs de trades et soldes continuent à
s'accumuler sur tout le backtest, y compris aux changements de cycle.

Ordre quotidien (annoncé avant modification du moteur)
-----------------------------------------------------
1. Valoriser les comptes existants avec les cours du jour ou le dernier cours
   connu pour les positions sans cotation ; aucun cours futur.
2. Actualiser I/H et tester le dépassement avant les ventes et achats habituels.
3. Si la protection est en liquidation, donner priorité à sa vente via
   _close_open_position ; exécuter uniquement sur un cours courant positif.
   Sinon, conserver les sorties Push, Couloir, GM et autres règles existantes.
4. Si liquidation en attente : bloquer allocations et achats pour tout le jour,
   même si la dernière position est vendue ce jour-là. Aucun double SELL.
5. Sinon, conserver la sélection/allocation habituelle ; neutraliser les apports
   illimités après les allocations et avant les achats, aux mêmes cours.
6. Exécuter les achats habituels puis les compteurs et snapshots existants.
7. Archiver le cycle si toutes ses positions ont été liquidées. Le lendemain,
   repartir à 100 avec la valeur nette restante, sans changer les comptes.

Si le capital net est épuisé après des pertes FIXED, conserver les réserves
négatives. Les achats attendent une valeur nette positive permettant de
financer un nouvel indice ; de nouveaux apports illimités peuvent la rétablir.

Chemins d'exécution et stockage
------------------------------
- run_backtest_task / run_backtest_job_task -> run_backtest : même protection
  pour toutes les méthodes et pour large_result_mode.
- run_backtest_kpi_only : si la configuration de protection est explicitement
  présente, délègue au moteur commun en mode sans lignes quotidiennes détaillées
  (max_days conservé). Le chemin désactivé reste identique. Les jeux n'exposent
  pas cette option ; aucun changement des tâches, de Celery ou de Redis.
- JSON normal et JSON volumineux : cycles dans portfolio.protection,
  index/sommet/drawdown/attente/marqueurs dans portfolio.daily,
  motifs de ventes dans les événements conservés même en mode volumineux.
- Déport json.gz : ne retire que les tableaux quotidiens par ticker ; les cycles,
  les marqueurs et les événements restent dans le JSON du backtest.
- Parquet optionnel existant : les lignes détaillées portent le motif de vente ;
  le résumé des cycles reste dans le JSON. Aucun nouveau stockage obligatoire.
- Configuration : settings.portfolio_protection = {enabled, threshold_pct}.
  Absente = désactivée. Aucun changement de schéma ni migration.
  BacktestForm valide 0 < seuil < 100, initialise la création/édition, sauvegarde
  les paramètres et les inclut dans l'invalidation des résultats existants.
  Les snapshots/restaurations et copies existants de settings les préservent.
- Résultats UI : courbes existantes préservées, marqueurs de chaque exécution
  de liquidation sur la courbe d'equity, tableau des cycles et aide partagée.
  Les dates des marqueurs sont ajoutées aux points sous-échantillonnés.
